# Wiki material

Ready to paste onto <https://wiki.postmarketos.org>. Nothing here is live until someone with a
wiki account creates the page.

## Create `Infinix X6525 (infinix-x6525)`

Copy `infinix-x6525.mediawiki` to that title. Fill in the two marked fields (`storage`, and a photo
if you want one) and your wiki username under Maintainers.

Leave `booting = no` and `packaged = no`. That is honest - nothing has run on the hardware yet - and
it is also what unblocks the pmaports merge request:

- `.ci/lib/check_devices_in_wiki.py` fails a device that is not on the Devices page at all. The
  `--booting` requirement ("devices must be in the upper table") is only applied to devices in
  pmaports main and stable; a `device/testing` package only has to appear somewhere on the page.
- The tables on the Devices page are generated by Cargo queries over the infobox, not written by
  hand. The non-booting table is `where Devices.Booting = 0`, so a page with `booting = no` lands
  there by itself. There is no table row to edit.

## When it first boots

Raise `booting = yes` **and** `packaged = yes` together, never one without the other:

- `booting = yes` with `packaged = no` matches no query at all - the non-booting table wants
  `Booting = 0`, every other table wants `Packaged = 1` - so the codename would disappear from the
  page and the CI check would start failing again.
- `packaged = yes` should be true by then anyway, since it means the device package is in pmaports.

Then fill in the `status_*` values as each is verified on the phone; a blank one renders as
"untested" per the legend at the top of the Devices page. `status_uboot_*` describe the chainloaded
U-Boot, and `whet_dhry` is the optional benchmark.
